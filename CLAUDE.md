# CLAUDE.md: admin (An Phat ERP back-office)

This is the engineering standard for this app, and every change must follow it. Paths are relative to `admin/`. Sibling apps live at `../ecom` (storefront, the root zone) and `../pos` (POS, mock-only).
Rule of thumb: copy the **newest exemplar** named here, not whatever file sits closest. The codebase contains several generations of patterns.

## 1. Overview

- **Purpose.** Internal ERP for An Phat, a manufacturer and seller. It covers sales orders, the product catalog and collections (which feed the ecom storefront), customers, employees/attendance/payroll, warehouses and stock movements, production batches, utilities (meters, usage, invoices), reports, site settings for ecom, and per-user page permissions. The UI is bilingual (vi default, en). Currency is VND.
- **Stack.**
  - Next.js **15.2.8** (App Router) and React 19, TypeScript 5 with `strict`.
  - TypeORM `^0.3.24` + `pg` on Postgres, using `reflect-metadata` and decorators.
  - `jsonwebtoken` auth; zod `^3.24` (server only).
  - Tailwind 3, shadcn/Radix (v0.dev build, double quotes), lucide-react, recharts, date-fns, react-datepicker.
  - `aws-sdk` v2 for S3, MailerSend for email, swagger-jsdoc and swagger-ui-react.
  - The app was generated by v0.dev (package name `my-v0-project`).
- **Package manager: pnpm.** `pnpm-lock.yaml` is current. `package-lock.json` is stale; do not update it. The Docker image uses Node 18-alpine.
- **Zone.**
  - The app is served to browsers as `/admin` through ecom's `rewrites()`: `localhost:3030/admin/*` → `admin:3000/*`, with the prefix stripped.
  - `next.config.mjs` has **no `basePath`**. It only sets `assetPrefix: "/admin-static"`, `typescript.ignoreBuildErrors`, `eslint.ignoreDuringBuilds` and `images.unoptimized`.
  - The `/admin` prefix for links and fetches comes from `NEXT_PUBLIC_BASE_ZONE` (compose sets `/admin`). `NEXT_PUBLIC_ADMIN_BASE_PATH` overrides it if set.
- **Ports** (root `../docker-compose.yml`): admin `4000:3000`, ecom `3030:3000`, pos `4001:3000`, Postgres `5433:5432`, DB `anphat_erp`. Always use `http://localhost:3030/admin`. Opening `:4000` directly with the zone env set gives 404s.
- **Shared DB.** One Postgres DB is shared with ecom. **This app owns the schema and all migrations.**

- **No linting.** `pnpm lint` maps to `next lint`, but there is no ESLint config or dependency, so it prompts for interactive setup. Do not configure ESLint unless asked.
- Do not run `./docker-compose.yml` (the legacy standalone stack, service `app`) alongside the root compose. Both bind 3030 and 5433.
- `.env.example` lists the env keys. Env vars are read through `constants/env.ts` (`env.X`); the one exception is `NEXT_PUBLIC_ADMIN_BASE_PATH`, read directly in `constants/nav.ts#getAdminBasePath`. Mismatch: the example file has `NEXT_PUBLIC_PAY_PERIOD_START`, but the code reads `NEXT_PUBLIC_SYSTEM_PAY_PERIOD_START`. `NEXT_PUBLIC_*` values are inlined at build time.
- Legacy: `env.JWT_SECRET` and `env.DATABASE_URL` have hard-coded fallbacks in `env.ts`. Leave them alone and do not copy the pattern.
- `node_modules` may be missing in a fresh codespace. Run `pnpm install` before `tsc` or migrations.
- `AUTH_ACCESS_TOKEN_SECRET` is required (32+ characters, no fallback, different from the legacy `JWT_SECRET`). Without it every login fails with 500. For quick session tests, set tiny `AUTH_*_SECONDS` values in `.env` and recreate the container.
- Migration CLI: run it on the host (Node 22). Under the Docker image's Node 18 it fails, because `uuid@13` is ESM-only. Point `DATABASE_URL` at the local database for that one command: `.env`'s active `DATABASE_URL` may be a shared remote (Neon) database, and `migration:gen`/`migration:revert` must never run against it.

## 4. Architecture and data flow

**Layers:** UI (page / page-client / components) → hook → `lib/httpclient` → `app/api` route → `lib/services` → `AppDataSource.getRepository(Entity)` → Postgres. There is no DI and there are no repository classes. Services are module functions. `UserService`, `PasswordResetService`, `EmailService` and `CommonService` are classes created with `new`.

**Read flow (pattern A, newest; use this for list and detail pages).** Exemplars: orders AP-127, employee AP-129.
1. `app/<f>/page.tsx` is an async server component with `export const dynamic = "force-dynamic"`. It awaits `searchParams` or `params`.
2. It calls `get<F>PageData(searchParams)` from `lib/services/<f>PageService.ts`. That service parses and whitelists params, calls `await ensureDataSource()`, calls the domain service, serializes entities to plain JSON (dates become ISO strings) and **never throws** (it returns an empty fallback and logs).
3. It renders `<ERPLayout><FPageClient key={JSON.stringify(params)} initialData={...} /></ERPLayout>`.
4. The hook (`hooks/use-<f>s.ts`) keeps all list state in the URL: `router.push/replace` inside `useTransition`, and a 500 ms debounced search with `replace`.
5. Mutations go through httpclient → API, then `startTransition(() => router.refresh())`.

In this pattern reads skip `/api`; only mutations use it.
- **Pattern B (hybrid: stock-change, customers, produce):** the server supplies the first data and the client refetches via httpclient. stock-change and customers guard this with `hasHydratedInitial = useRef(...)`; produce refetches unconditionally in `onInit`.
- **Pattern C (legacy all-client hooks):** home, utilities, attendance, invoices, payroll, settings, utility-usage, products, collections, warehouse, permissions. Keep B and C only when editing those features.
- **Reports** have no report endpoints. Hooks page through list APIs with a `do { ... } while ((page-1)*LIMIT < total)` loop (`getAll<X>ByFilter`, or inline in `hooks/useReportProductionV2.ts`) and aggregate in memory with date-fns (`components/production-report-v2/*`). Known bug: `useReportOrder` calls `getOrders()` with no params, so it only sees the API's default 20 rows. Do not copy it.

**Auth.**
- **Login:** `POST /api/auth/login` `{username,password}` → `UserService.verifyUser` (bcryptjs) → only active `super_admin`/`admin`/`manager`/`staff` (`lib/auth/session-policy.ts`, else 403 `account_not_allowed`) → two httpOnly `SameSite=Strict` cookies:
  - `admin_access_token`: 15-min JWT `{ userId, sid, typ: "access" }` (HS256, pinned iss/aud), signed with `AUTH_ACCESS_TOKEN_SECRET`, Path `<base>` (`/admin`).
  - `admin_refresh_token`: opaque 30-day token, only its sha256 stored in `refresh_tokens` (`lib/services/refreshTokenService.ts`), Path `<base>/api/auth`. The browser matches Path against the `/admin/...` URL, not the rewritten one.
  - Lifetimes come from the `AUTH_*` env keys (`lib/auth/session-config.ts`); `.env.example` documents them.
- **Refresh:** `POST /api/auth/refresh` (cookie-authenticated, no access token needed) issues a new access token and, when the refresh token has 7 days or less left, a new refresh token. Rotations stay in one session family; every change to a family runs under a Postgres advisory lock. A replayed old token revokes the family (`reuse_detected`). Password fingerprint, `active` and role are re-checked on every refresh. 401 `{ code }` ends the session; 5xx is transient. Logout, re-login, password reset and deactivation through `PUT /api/users/[id]` revoke sessions.
- **Login, refresh and logout** require the header `X-Admin-Auth: 1` and reject `Sec-Fetch-Site` other than `same-origin` (`getAuthRequestGuardError` in `lib/utils.request.ts`). forgot/reset-password stay unguarded for ecom.
- **API check:** `getUserFromRequest(req)` reads `admin_access_token` or `Authorization: Bearer` and verifies it (`IAccessTokenPayload`). **Use `user.userId`.** No route checks roles or page permissions except `PUT /api/users/[id]` (active super admin).
- **Client:** `AuthProvider` keeps the user in localStorage `"user"` plus lifetimes in `admin_session` (no secrets), and exposes `useAuth()` → `{ user, login, logout, isAuthenticated, isAdmin, isSuperAdmin }`. It refreshes on load, focus and visibility, redirects an idle tab when the refresh token expires, and follows other tabs through `storage` events. An expired session goes to `ADMIN_ROUTES.login("reason=session_expired&next=…")` and returns to that page after login. `AuthGuard` redirects to login (with `next`) unless the path is an auth page (`getAuthPagePaths()` in `lib/auth/return-path.ts`). **New public pages must be added there.**
- **Page permissions:** `ERPLayout` fetches `getUserById(user.id).permissions` (`UserPagePermission {userId,pageId,granted}`), filters the sidebar, and shows "access denied" when `pathname` equals a nav child `href` whose `id` is not granted. admin and super_admin bypass the check.
  - The pageId is `navItems[].children[].id` in `constants/nav.ts`.
  - Detail pages and pages without a nav entry are always allowed.
  - `DEFAULT_ROLE_PERMISSIONS` is dead code.
- **Server pages do no auth check**, and there is no `middleware.ts`. Their data ships in the RSC payload regardless of login.

**Multi-zone implications.**
- Every browser URL must include the zone prefix. Use `ADMIN_ROUTES.*()` / `adminHref()` for navigation and `apiHref()` / `createApiUrl()` for fetches.
- Cross-zone navigation (to ecom or pos) must be a full page load (`<a href>` / `window.location.href`), not `next/link`.
- To build absolute URLs on the server, use `getPublicOrigin(req)` (`lib/utils.request.ts`; it honours `x-forwarded-*` from the ecom proxy).
- Root-relative public assets (`/app-logo.png`) are actually served from `../ecom/public/`. A new admin asset must be copied there too, or referenced through `adminHref("x.png")`.
- All zones share one origin, so cookies and localStorage are shared. The `language` key is intentionally shared with ecom. New localStorage keys need a prefix, e.g. `admin_` (`admin_session`, `admin_session_end`). Admin cookies are scoped to `/admin` and `/admin/api/auth`, so ecom and pos never receive them; the legacy `token` cookie is only cleared.

**Cross-app contracts.** ecom calls these endpoints; keep them **public** and keep their request/response shapes: `/api/auth/forgot-password`, `/api/auth/reset-password`, `/api/settings/type/[type]`.
- ecom logs in separately with next-auth against the same `users` table. Sessions are not shared.
- ecom writes `orders`, `customers`, `addresses`, `carts` and `notifications` with its own entity copies. Those copies only number records (`ORD`/`CUS`), so orders created in ecom get no activity log, stock-out or completion handling.

## 6. Conventions (MUST follow)

**General**
- Use the `@/` alias (the app root) for cross-folder imports. Use double quotes. There is no formatter; match the file's semicolon style (API and services use semicolons, components mostly don't).
- Type props interfaces as `interface I<Component>Props` in new files. Older files (including parts of `components/employees/`) use `XProps` or `Props`; don't copy that.
- New domain types are `I`-prefixed (`IUtilityUsage`, `I<X>Filters extends IBaseFilters`), plus a `<X>SortBy` union.
  - The legacy unprefixed types (`Product`, `Order`, `Employee`, `EmployeeFilters`) stay as they are.
  - Entities import them aliased: `import type { Product as IProduct } from "@/types"`.
- Every enum lives in `types/enums.ts` as a string enum. New enums use value equal to the key, because filter modals iterate `Object.keys` and then use the key as the value. Legacy exceptions: `StockChangeType` (`stock-in`/`stock-out`), `ProductionStatus` (`in-progress`, `lack-material`) and `StockChangeStatus.inTransit` (`in_transit`); use `Object.values` for those. Values are baked into PG enum types, so renaming one needs a migration.
- Read env only via `env` from `@/constants/env`. Never add secret fallbacks.
- Put `"use client"` on every component or hook that uses hooks, even if its current importer is a client component.

**Entities (`lib/database/entities/<kebab>.entity.ts`)**
- `@Entity({ name: "snake_plural" }) export class XEntity extends BaseEntity implements IX`. `BaseEntity` is our own class (uuid `id`, `created_at/by`, `updated_at/by`).
- Import `./base.entity` and sibling entities by **relative path**. Never import from the entities barrel inside an entity file (circular imports; fixed in AP-124). Type relation properties with `@/types` interfaces, and reference classes only inside `() => XEntity`.
- Column rules:
  - New columns get an explicit `name: "snake_case"`. FKs use `@JoinColumn({ name: "<rel>_id" })`.
  - Always give an explicit `type`: `"float"` for money and quantities, `"int"` for counts, `"timestamp"` for dates, `"jsonb"` for line items and snapshots (the project uses jsonb, not child tables), `"text", array: true, default: () => "'{}'"` for arrays.
  - Enums: `type: "enum", enum: X`, or `enumName` to reuse an existing PG type.
- Name constraints and indexes explicitly in the entity with `@Unique("UQ_...")` and `@Index("IDX_...")`; the exemplar is `setting.entity.ts`. If a name exists only in a hand-written migration (as with `password_reset_tokens`), `migration:gen` will try to drop it.
- Business documents get `@Column({ unique: true }) number?: string` plus `@BeforeInsert generateNumber()` → `new CommonService().getEntityNumber(XEntity, "ABC")`.
  - The prefix is **exactly 3 characters** and must be new, because `getEntityNumber` sorts on `SUBSTRING(number FROM 5)`. Taken: ATD COL CUS EMP INV ORD PAY PRD (product `sku`) PRN STC UUS UTL WHS.
  - In batch or transaction inserts, pass `currentNumber` (see `stockChangeService.transferWarehouse`).
- Hooks may only do numbering and pure derived fields (copy `utility-usage.entity.ts` `syncDerivedFields`). New side effects go in services with explicit transactions.
- Register every new entity in **both** `lib/database/entities/index.ts` and the explicit `entities: [...]` in `lib/database/typeorm.ts`.
- Entities, services and `lib/utils*` load under the ts-node CommonJS migration CLI. Never import `next/headers`, `server-only` or React components into them.

**Services (`lib/services/<camel>Service.ts`)**
- A new resource copies the `utilityUsageService.ts` **names and write bodies**: `get<X>sService`, `get<X>ByIdOrNumberService`, `add<X>Service`, `update<X>Service`, `delete<X>Service`. When extending an existing file, match that file's names. Do not copy three things from it:
  - its list sort, which interpolates `sortBy` without a whitelist;
  - its id-or-number lookup, which has no UUID guard, so Postgres throws on a non-uuid `id`;
  - its `throw` on a missing record (see below).
- The list is `createQueryBuilder("alias")` + `andWhere` with **named params**, a `searchTerm` `ILIKE %term%` search wrapped in `( ... OR ... )` (`utilityUsageService` / `orderService`), a **whitelisted** `sortBy` (a `X_SORT_FIELDS: XSortBy[]` array) with a safe `ASC|DESC`, `skip/take` and `getManyAndCount`. It **returns `{ data, total, page, limit }`**. The whitelist exemplar is `employeeService.getEmployeeByFilter`, but employee searches a `name` field instead of `searchTerm`; new resources use `searchTerm`.
- Id-or-number lookup: `UUID_PATTERN.test(v) ? [{id:v},{number:v}] : [{number:v}]` (`employeeService.getEmployeeByIdOrNumber`, `productionService`). `UUID_PATTERN` is file-local there, so copy it; it is not exported.
- Writes:
  - Create: `repo.save(repo.create(data))`.
  - Update: `findOneBy` → `merge` → `save`.
  - Delete: `findOneBy` → `remove` → `true`.
  - Missing record: `get` returns `null`, and `update`/`delete` return `null`/`false` so the route can answer 404. A plain thrown `Error` reaches the route's `catch` and becomes a 500, which is what `utility-usage/[id]` does today.
  - `employeeService.updateEmployee`/`deleteEmployee` (`repo.update`/`repo.delete`) and `customerService.updateCustomer` are legacy. Don't copy them.
  - Hooks only fire on `save()` of an entity instance.
- Get repos per call (`AppDataSource.getRepository(X)`), or `manager.getRepository(X)` inside `AppDataSource.transaction(async manager => ...)`. Any multi-row or multi-table write must be in a transaction.
- Function services do **not** call `ensureDataSource()`. Routes and page services must call it first. The `UserService` and `PasswordResetService` classes call it internally.
- Errors: throw `new Error("<message>")` for unexpected failures, which the route turns into a 500. Throw inside a transaction to roll it back. For 4xx business errors, define a typed error with `status`, modelled on `PasswordResetRequestError` in `passwordResetService.ts`, and map it in the route with `instanceof` (as `api/auth/forgot-password` does).
- Log with a tag: `console.error("[<file or api path>] Failed to ...", { ctx, error })`.
- Page services (`<f>PageService.ts`) copy `employeePageService.ts`:
  - Define `<F>PageSearchParams` and `I<F>PageData` in the file.
  - Use parse helpers, `PAGE_SIZE_OPTIONS = [5,10,20,50,100]`, and an **explicit field-by-field serializer using `toIsoDate`** (not `JSON.parse(JSON.stringify())`).
  - Detail DTOs with string dates go in `types/<f>-detail.ts` (e.g. `types/employee-detail.ts`).

**API routes (`app/api/<kebab-resource>/...`)**
- Exemplars: `app/api/employee/[id]/route.ts` (item), `app/api/utility/route.ts` (collection).
- Handler order:
  1. `const user = getUserFromRequest(req); if (!user) return 401 { error: "Unauthorized" }`, before `try`.
  2. `try { await ensureDataSource(); ... }`.
  3. Parse query from `new URL(req.url).searchParams`.
  4. `Schema.safeParse(await req.json())`; on failure return 400 `{ error: "Invalid input", details: parse.error.errors }`.
  5. Call the service.
  6. `catch` → tagged `console.error` + 500 `{ error: message }`.
- Item params: `interface I<X>RouteContext { params: Promise<{ id: string }> }` with `const { id } = await params`. Use `decodeURIComponent(id)` for id-or-number routes. Only `employee/[id]` and `production/[id]` do this today; every other dynamic route still uses the legacy `{ params: { id: string } }` typing.
- Responses: list returns the service's `{ data, total, page, limit }` as-is. Get and update return the raw entity (200). Create returns the entity with **201**. Delete returns **`new NextResponse(null, { status: 204 })`**. Not found is 404 `{ error: "Not found" }` (from a `null`/`false` service result), a business-rule failure is 400 `{ error }`. Errors always use the `error` key, never `message`.
- Query params: `page` (default 1), `limit` (20), `sortBy` (`createdAt`), `sortOrder` (`desc`), free text **`searchTerm`** (11 routes, e.g. `orders`, `utility`; `employee` uses `name`, which is legacy), ranges `<field>From/<field>To` (`dateFrom/dateTo`, `costFrom/costTo`), relations `<rel>Id`. Numbers use `Number(x) || fallback`; optional strings use `get(x) || undefined`.
- Audit fields: `createdBy/updatedBy: user.userId`. No existing route sets them correctly (only `utility-usage`, with the broken `user.id || user.username`), so this is a rule for new code.
- Non-CRUD actions go in `app/api/<resource>/<action>/route.ts`, using **POST** for mutations.
- Swagger JSDoc is optional; if you add it, copy the `app/api/products/route.ts` format.

**Validation (zod, server only)**
- Put schemas in `app/api/<resource>/<resource>.schema.ts`: `export const XSchema = z.object({...})` and `export const UpdateXSchema = XSchema.partial()` (as in `utility-usage`, `utility`, `invoice`). The `CreateXSchema` + `UpdateXSchema` naming in orders, stock-change, warehouse and payroll is also fine. Mark genuinely required fields as required. PUT must parse with `UpdateXSchema`; `employee/[id]` reuses the full schema, which is legacy.
- Use `z.nativeEnum(Enum)` for enums, `z.coerce.date()` for dates, `z.object({ id: z.string() })` for relations, `z.string().uuid()` and `z.number().positive()` where strict (`warehouse/transfer/transfer.schema.ts`), and `superRefine` + `ctx.addIssue` for cross-field rules (`ProductTierPricesSchema` in `products/product.schema.ts`).
- Pass the parsed data to services typed with interfaces, not with `as XEntity` casts.

**HTTP client (`lib/httpclient/<kebab>.client.ts`)**
- Copy `utility-usage.client.ts`. It is the only client with the target names, the `Date` handling and the `getAll...` loop. `employee.client.ts` has the same fetch shape, but its list function is called `getEmployee` and it has no `getById`, so don't copy its names.
- GET: `createApiUrl("/api/x")`, append non-empty params (`Date` → `formatYYYYMMDD`).
- **Use `apiFetch` from `@/lib/httpclient/base`, not `fetch`,** for every authenticated admin API call. It refreshes an expired session and retries once. Raw `fetch` is only for the auth flows in `auth.client.ts` (login, register, forgot/reset password, logout) and cross-origin URLs (the presigned S3 PUT).
- Mutations: `apiFetch(apiHref(...), { method, headers: {"Content-Type":"application/json"}, credentials: "include", body })`.
- **Every** function sends `credentials: "include"`, checks `res.ok` and throws. DELETE returns the `Response`; never call `.json()` on a 204.
- Name functions `get<X>sByFilter / get<X>ById / add<X> / update<X> / delete<X>`, and add a `getAll<X>sByFilter` loop if reports need every row. Add the file to `lib/httpclient/index.ts` and check that no exported name clashes, since the barrel re-exports every client flat.
- Never write `fetch("/api/...")` or `apiFetch("/api/...")` without `apiHref`.

**Formatting (all from `@/lib/utils`)**

## 7. Recipes

**R1. Add an entity and migration**
1. Types: `types/<x>.ts` with `IX extends IBase` (optional fields), `IXFilters extends IBaseFilters`, `XSortBy`. Add enums to `types/enums.ts`, then export from `types/index.ts`.
2. Entity: `lib/database/entities/<x>.entity.ts`, following §6 Entities. Combine three exemplars:
   - `utility-usage.entity.ts` for relations, derived fields and numbering. Its columns have no `name:` and its table name is singular; don't copy those.
   - `password-reset-token.entity.ts` for snake_case column names with explicit types.
   - `setting.entity.ts` for named `@Unique`/`@Index`.
   If the entity has a `number`, pick a new 3-letter prefix (§6).
3. Add the inverse relation on the related entity and its interface if needed.
4. Register it in `entities/index.ts` **and** the `entities` array in `lib/database/typeorm.ts`. Migrations need no registration, because `typeorm.ts` loads `migrations/*` by glob.
5. `pnpm migration:run` (the DB must be at head), then `pnpm migration:gen Add<X>Table` with a unique name.
6. Review the SQL. **Strip unrelated drift**; known noise includes nullability on `payroll_records."employeeId"` and `warehouse_products.*_id`, and the `password_reset_tokens` indexes/FK. Check that `down()` mirrors `up()`. Seed data uses idempotent `INSERT ... ON CONFLICT DO UPDATE` (`20260606-AddThemeSetting.ts`).
   - A hand-written migration needs a class timestamp greater than the latest (`AddProductTierPrices1782038400000`). TypeORM orders migrations by the class timestamp, not the file name.
7. `pnpm migration:run`, then `migration:revert`, then `migration:run` again. Commit the entity and migration together (exemplar commit `78864fb`).
8. If ecom reads or writes the table, mirror the columns (same `name/type/nullable/default`) into `../ecom/lib/database/entities/` in a separate ecom commit on the same ticket. Admin-only relations become plain FK id columns there.

**R2. Add an API resource**
1. Service `lib/services/<x>Service.ts` (§6 Services; copy `utilityUsageService.ts` naming and the `employeeService.getEmployeeByFilter` whitelist).

- **Schema:**
  - Set `synchronize: true`; edit old migrations; add migrations anywhere but here.
  - Change a shared table (users, customers, addresses, orders, products, collections, carts, cart_items, notifications, notification_settings) without mirroring the change to ecom.

- **Stock:** write `products.stock` or `warehouse_products.quantity` directly. Always create or save a `StockChangeEntity` with `status: completed`.
  - Remember that hooks re-fire on every save of a completed record, that deleting a completed stock change does not reverse stock, and that the order and production hooks are fire-and-forget and open their own transactions.
  - Do not add more hook side effects.
- **Data access:**
  - Use `repo.update()` or QueryBuilder updates on entities with hooks or relations (they skip hooks); `repo.save(plainObject)` without `create`.

The ones that whitelist are employee, customer, stock-change, production, order and `warehouseService.getAllWarehouses`.
  - Put a number prefix that isn't 3 characters, or loop over inserts without `currentNumber`.
  - "Fix" the `AppDataSource` singleton or `ensureDataSource` race as a side effect of a feature.
- **API legacy shapes:**
  - Synchronous `params.id` (`products/[id]`, `collections/[id]`, `customers/[id]`, `warehouse/[id]` DELETE), or `{ params: { id: string } }` typing (every dynamic route except `employee/[id]` and `production/[id]`).
  - `{ data, pagination }` lists (users, permissions); `{ message }` errors or `Schema.parse` + ZodError catch (`users/[id]`); `error.flatten()` details.
  - `search`, `name` or JSON-in-query ranges (`priceRange`) instead of `searchTerm` and `From/To`.
  - Mutating GETs (`payroll/sync`); duplicated create/update schemas; string-matching error messages to pick a status.
- **Auth and security:**
  - `user.id || user.username` from the JWT (`utility-usage` routes; always undefined).
  - New unauthenticated routes. `upload-url` is a known hole, and `register` is public and creates staff (they cannot sign in once deactivated). `/api/auth/refresh` is intentionally cookie-authenticated.
  - Returning `UserEntity` without stripping `password`/`passwordSalt` (they are not `select: false`).
  - Trusting localStorage `user` or `isAdmin` for anything security-relevant. The API enforces no roles, so add a server-side role check for sensitive new endpoints (for example, load the user by `user.userId` and check `role`).
  - `NEXT_PUBLIC_*` secrets, or new client imports of `lib/s3.ts` (it ships AWS keys to the browser). New S3 work belongs server-side (copy `../ecom/lib/s3.server.ts`, SDK v3) behind an authenticated route.
  - Committing secrets or printing values from `docker-compose.yml` or `.env`.
  - Server pages that load sensitive data have no auth today. If you add a check, verify the `admin_access_token` cookie with `verifyAccessToken` inside the page, never inside services. A Server Component cannot refresh (it cannot set cookies), so redirect to the login page with `next` instead. No exemplar exists.
  - Side effects before the auth check: `apiFetch` replays a request once after a refresh, so every handler must call `getUserFromRequest` before anything else.
- **UI legacy:**
  - Full `"use client"` pages with inline column defs (`app/payroll/page.tsx`) or `useParams` in pages (`app/products/[id]/page.tsx`); pages without `ERPLayout` (`app/permissions/*`); mock pages.

  - Inline status-color switches, inline spinners, hardcoded English, `$` currency, passing `t` as a prop, `JSON.parse(JSON.stringify())` serializers, `window.location.reload()` after saves (use `router.refresh()`).

## 9. Git conventions

- **Commit subject:** `<type>: <lowercase summary>. #Refs AP-<n>`. GitHub squash-merge appends ` (#<PR>)`.
  - Types in this repo, by frequency: `feat` (most), `refactor`, `enhance`, `fix`, `hotfix`, `build`. The root repo also uses `chore` and `doc`.
  - Real examples:
    - `feat: implement price base on quantity. #Refs AP-108 (#66)`
    - `feat: implement employee management pages. #Refs AP-129`
    - `enhance: stock-change pages. #Refs AP-124`
    - `hotfix: remove auth for get brand type api`
    - `build: setup typeorm migration scripts (#36)`
  - Always include the ticket when one exists.
- **Branches:**
  - Feature branches: `AP-<n>-<kebab-desc>` (e.g. `AP-129-employee-page-enhancement`).
  - Other patterns: `hotfix-*`, `release-YYYYMMDD`, `YYYYMMDD-sync-prod`.
  - `dev` and `main` have diverged, so confirm the base branch with the user before branching.
  - PRs are squash-merged. Commit only when asked.
- **Submodule:** this app is the submodule `admin/` (repo `RobertVo93/an-phat-erp`, `branch = main`) of the root `anphat` repo.
  - Commit and push here first. Then in the root run `git submodule update --remote --merge`, `git add admin`, and commit `chore: bump submodules`.
  - A cross-app feature uses one ticket, with a separate branch and PR in each repo (e.g. AP-108: admin `#66`, ecom `#34`).
- Commit the entity and its migration together. Ecom mirror or port changes go in a separate ecom commit with the same `#Refs AP-<n>`.
